name: methods-only-publication
description: Prepare and verify a public methods repository while excluding local datasets, actual geometry, personal records and operational details.
---

Translate the user's publication boundary into an explicit file allowlist. Preserve the original project privately. Newly write or review every line of generalised modules; removing a data directory alone does not remove embedded parameters, keys, endpoints or records from source.

Use runtime-generated synthetic test inputs. Reference public publisher landing pages without copying source records. Create any requested illustration from fictional forms without reference data. Inspect binary metadata as well as visible pixels.

Inspect the target's existing refs before preparing history. Preserve legitimate history with a normal fast-forward; do not force-push to resolve an unexpected parent. Inspect every reachable commit for disclosure. Use the account's public no-reply identity rather than an internal email unless the user explicitly requests otherwise.

Export exactly the candidate commit. Compare every path, file mode, blob and hash against the allowlist. Reject symlinks, submodules, archives, data files and unreviewed binaries. Run synthetic tests, content checks and a secret scanner against the export. Automated scans cannot prove that no sensitive semantics remain: review the content independently.

When the user requires a reviewer, provide the exact commit archive, hash manifest, history, refs, tests, proposed push command and metadata. Obtain the required agreement against that concrete candidate before external publication. If files change, regenerate the evidence and renew the review for the new commit.

Publish exactly the approved branch from an isolated clean checkout with no local data. Keep the private project remote-less or enforce an equivalent exact-tree gate. Do not push all refs, tags, stashes or unrelated branches. Verify the remote commit, tree, CI and requested About fields after publication. State concrete omissions or blockers rather than treating a local note as completed remote work.
